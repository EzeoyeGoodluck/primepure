# PrimePure Cleaning Solutions — website

Plain HTML/CSS/JS, generated by a small Node script. Nothing to install.
Deployed on Vercel from `public/`.

## What gets built

50 pages, from three data files:

| Pages | Where they come from | Example URL |
| --- | --- | --- |
| Home, About, Contact, Quote, 404 | `src/pages/` | `/about` |
| Services index | `src/templates/services-index.html` | `/services` |
| 7 service pages | `src/data/services.json` | `/services/end-of-tenancy-cleaning` |
| Areas index | `src/templates/areas-index.html` | `/areas` |
| 9 town pages | `src/data/towns.json` | `/areas/wolverhampton` |
| 28 town + service pages | `src/data/pairs.json` | `/areas/walsall/carpet-cleaning` |

Town + service pages are only generated for towns marked `"primary": true`
**and** which have an entry in `pairs.json`. That is deliberate: a page with
nothing specific to say about that town and that job is worse than no page.

## Folder layout

```
site.config.json      domain, phone, email, form inbox, image paths
src/data/
  services.json       the 6 services: checklists, process, FAQs
  towns.json          the 9 towns: postcodes, neighbourhoods, local FAQs
  pairs.json          one hand-written intro per town + service combination
  reviews.json        real customer reviews (empty until you have some)
src/pages/            one-off pages (home, about, contact, quote, 404)
src/templates/        page shapes filled from the data
src/partials/         layout, quote form, closing call-to-action
public/               the generated site — do not edit its .html by hand
public/assets/        styles.css (colours at the top), main.js, images
build.mjs             the generator
```

## Adding things

**A new town** → add an object to `src/data/towns.json` and rebuild. It gets a
town page, a footer link, a tile on the home page and `/areas`, and a chip on
every service page.

**Town + service pages for it** → set `"primary": true` on the town and add a
block to `src/data/pairs.json` with one intro paragraph per service. Write them
properly; do not paste the same paragraph with the name changed.

**A new service** → add an object to `src/data/services.json`. It appears on the
home page, `/services`, every town page and the quote form's dropdown.

## Running it

```bash
node build.mjs          # build into public/
npm run preview         # build, then serve public/ locally
```

## Design

Colours and type are at the top of `public/assets/css/styles.css`.

- Royal blue `#0050C0` — sampled from the logo, `rgb(0, 80, 192)`. Top bar,
  buttons, links, tick marks.
- Navy `#072B66` and ink `#051C3C` — the same hue darkened. Navy is for
  full-width bands only, where royal blue would overwhelm; ink for headings
  and the footer. Anything that sits next to a button — the guarantee card,
  the at-a-glance panel — takes the royal blue, so two blues never clash in
  one eyeful.
- Gold `#A87F2E` (on light) and `#D9A93F` (on navy) — stars, numerals and small
  uppercase labels only. Never a gold button on a light background.
- Ivory `#F7F5F0` page background, Newsreader headings, Inter body.

## Reviews

`src/data/reviews.json` is an empty array. While it stays empty, the home page
and every town page show a **promises** block instead — three commitments that
can actually be checked. The moment you add a real review, that block is
replaced by the reviews.

```json
[
  {
    "text": "What the customer actually wrote.",
    "name": "Sarah J.",
    "area": "Tettenhall",
    "town": "wolverhampton",
    "service": "End of tenancy",
    "stars": 5
  }
]
```

`town` must match a slug in `towns.json`; it is what puts the review on that
town's page as well as the home page. Only paste what customers really wrote.

### Asking for them

Send this the day after a job, while it is fresh:

> Hi [name], thanks for having us today. If the place looked right, would you
> mind leaving us a quick Google review? It genuinely decides whether people
> round here find us. Takes a minute: [your Google review link]

Ask every customer for the first month. Ten honest reviews will do more for
enquiries than anything else on this list.

Set these in `site.config.json` when you have them — the build hides what is
blank rather than printing a placeholder:

- `companyNumber` — **a UK limited company must show its registered number and
  registered office on its website.** Until it is set, the footer says
  "Registered in England & Wales" with no number.
- `vatNumber` — leave blank if not registered.
- `whatsapp` — see above; currently the landline.

Also outstanding: a matched before-and-after photo pair (shoot the same corner
twice, same angle), and a decision on whether to show both the business address
and the registered office in `src/pages/about.html`.

## Forms

The quote and contact forms post to **FormSubmit** (free, no account) and arrive
as email at the address in `site.config.json`.

**The first submission triggers an activation email** to that inbox. Until
someone clicks the link in it, nothing is delivered. Send a test and check the
inbox and the spam folder.

## Deploying

Vercel → Add New → Project → import this repo → Framework Preset **Other** →
Deploy. `vercel.json` sets the build command, `cleanUrls` and asset caching.
Then Settings → Domains, and set `url` in `site.config.json` to match.
